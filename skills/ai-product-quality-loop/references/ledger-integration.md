# 质量闭环与规划台账交接

本参考只定义质量闭环如何使用已有规划台账，不复制或替代 `planning-with-files-zh` 的读写契约。规划 Skill 适用时，继续使用项目根目录 `.claude/` 下的现有文件。

## 文件职责

| 文件 | 质量闭环写入内容 |
|---|---|
| `task_plan.md` | 当前门禁、节点依赖、进入条件、后续任务和受影响范围 |
| `progress.md` | 唯一当前快照：门禁、节点、状态、已关闭证据、未验证边界、阻塞责任、下一步和用户决策点 |
| `findings.md` | 仍会影响后续执行或排障的稳定事实、证据限制和重复失败模式 |
| `changelog.md` | 实质阶段结果、验证、流程摩擦和用户反馈；按日期追加 |
| `decisions.md` | 会改变产品、架构、权限、范围或质量取舍的决定及其适用范围 |

不要把每次工具调用、临时观察或重复的状态副本写入台账。状态变化写入 `progress.md` 的唯一快照；有实质交付时在 `changelog.md` 留下历史记录；只有稳定且会复发的结论才提升到 `findings.md`。

## 当前快照最小字段

在 `progress.md` 中保持以下信息可直接读取；字段可并入现有结构，不要求创建新标题：

```markdown
- 当前门禁：Q1 / Q2 / Q3 / Q4
- 当前节点：
- 门禁状态：Passed / Passed for limited scope / Changes required / Review incomplete
- 已确认与关闭证据：
- 未验证边界：
- 阻塞与责任：
- 需要用户思考：无 / 具体决策及影响
- 下一步与停止条件：
```

“门禁通过”只表示声明范围内的路由条件满足，不等于产品价值、真实外部行为或后续门禁已经通过。证据入口失效或契约发生变化时，只回退受影响的范围。

## 收尾记录

质量闭环完成一个有实质结果的阶段后，在 `changelog.md` 记录：结果、范围、证据入口、未验证边界、流程摩擦和下一步。若本轮没有新增结果、决定或证据，不重复追加历史条目。用户明确改变取舍时，再同步 `decisions.md`；不要把普通工程判断升级成用户决策。

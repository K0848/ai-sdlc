# 交接、恢复与工程失败规则

仅在阶段交接、恢复、并行执行结果汇总、记录异常或处理工程失败时读取。本文件是质量闭环对交接、恢复和工程失败规则的唯一来源；不修改或复制通用规划 Skill 的台账读写契约。

## 交接摘要

主模型为本批分配项目内唯一标识，统一使用三级标题：

```markdown
### handoff-<批次任务标识>-<阶段>-<序号>
- 结果：日期、批次/任务、阶段及真实结论（完成／部分完成／受阻）。
- 完成与决定：实际交付和影响下阶段的决定；没有决定不强造。
- 依据：产物、审查、运行证据或版本入口；未验证直接标明。
- 承接：未完成事项、下一步和责任人/角色；没有遗留写“无”。
```

摘要通常为标题加 3–5 条短条目；字段可在不丢失结果、依据和承接的前提下合并。锚点只用小写英文字母、数字和连字符，例如 `handoff-b01-t02-plan-01`。同一文件内不得重复；正文可使用中文。执行者文档和主台账复制同一结果时沿用同一标识。新变化或更正使用下一序号，并链接原锚点，不改写旧结论；归档时先保证目标可读取，再更新所有引用，不能留下指向已删除或覆盖快照的孤立链接。

## 启动边界与准入

恢复与准入阶段先复用已有授权、当前项目约定和可用资源；只补真正缺失且会影响执行的边界：实际可用的执行者、审查者及备用方案，文件与外发数据范围，时间与费用预算，以及无进展、重复失败和授权外行动的升级条件。已有快照时从固定锚点读取并核对最近交接；首次运行没有快照时，从已确认需求、真实项目产物和当前授权建立准入状态，不读取或假定不存在的快照。缺少关键边界时只暂停受影响范围，并明确需要补齐的输入。

## 门禁快照字段

项目当前快照在需要跨门禁恢复时补充以下字段；字段缺失只阻塞依赖该状态的范围：

```markdown
- 当前门禁：Q1 / Q2 / Q3 / Q4
- 门禁状态：Passed / Passed for limited scope / Changes required / Review incomplete
- 权威输入：需求、架构、测试或执行文档入口
- 结论锚点：对应审查或交接的稳定链接
- 未验证边界：当前不能外推的行为或证据
- 下一门禁：
- 阻塞与责任：
```

门禁状态只是路由信息，不替代交接摘要、详细证据或产品决定。门禁通过后继续下一门；契约变化时回到受影响的最早门禁，已通过且未失效的范围沿用原结论。

## 完整行为交接

执行交接以可独立验收的完整行为为单位，必须提供或引用：权威需求与技术契约、可观察输入/输出和完成条件、源码/构建产物及其文件所有者、数据与状态所有权、真实依赖与并行安排、可运行验证入口、失败/恢复规则和上报边界。详细字段保持在已有架构与 Harness reference 中；本文件只维护交接如何记录、合并和恢复，避免复制契约正文。

验收矩阵的阶段续填约定见 [需求与验收 QE 评审](requirements-review.md)。交接恢复时沿用核心验收项的既有 ID 或稳定锚点，按本批影响补关联；单一记录者维护矩阵状态和链接，执行者证据仍以其独立文档为准，不能以映射存在替代实际验证。

## 单一记录者与合并顺序

主模型或明确指定的单一记录者维护共享项目台账。派发时必须登记每个执行者的独立执行文档路径、所有权和交接标识；优先复用已有文档，共享文档则为任务建立互不冲突的结果落点。执行者先把摘要和证据入口写入所属文档，再通知主模型读取；消息只传文档位置和标识，不能作为唯一结果载体。

主模型读取后按标识去重，先合并 changelog，再更新 progress/当前快照。复制摘要或证据时，检查相对链接是否因目标目录变化而需要重定位；能稳定保留时优先直接引用原执行文档锚点，若复制到 changelog 则改为相对目标目录可解析的链接。合并前，执行文档是待交接结果的权威入口；合并后，主台账是阶段状态入口，详细证据仍引用原文档。普通工具调用和单次失败不逐条写入阶段摘要。

## 恢复与幂等

- 快照有固定锚点：从锚点读取最近交接、核对产物和未结事项，继续正确阶段，不默认重跑全流程。
- 摘要已写、快照未更新：核对实际状态后仅补齐滞后快照，同步当前事实和最近相关交接的标准 Markdown 链接；若旧链接只指向更早阶段，更新或补入已有最近记录锚点，不能只改状态文字，也不新增历史。快照已推进、摘要缺失：用可核验产物补录并注明补录时间与依据。修复滞后快照或重建丢失链接不属于新阶段结果；没有新增结果、决定或证据结论时沿用已有标识，不新建锚点或历史摘要。无法复原则写“记录缺失／未验证”。
- 同一标识再次执行且无新结果时不追加；恢复更正若只是让快照与已有交接一致，也不追加。只有真实结果、决定或证据结论改变时才用下一序号并链接原记录，不能用新标识绕过去重。旧链接保持有效。
- 主模型汇总前中断：恢复后读取已登记的执行文档；缺少结果文档时视为未交付，不能依据消息里的“完成”推进。
- 证据入口缺少或链接失效时，只阻塞依赖该证据的范围；其他有充分证据的工作继续。不能把修复链接本身当作行为通过。

## 工程失败与返回

普通测试失败、补丁定位、构建问题留在实现者的实现→验证→定位→修复→回归循环，不送入通用规划失败计数。契约缺口回到受影响的方案阶段；台账异常只报告记录状态，不能据此宣布工程失败或成功。新授权、预算耗尽或边界内无法解除的阻塞才升级。

同类缺陷连续两轮未解决且无新增有效证据时先诊断原因（交接缺口、Harness/环境故障、实现路径或契约变化），再在权限和预算内调整方法继续；不原样重复派发，也不默认换模型。阶段推进不需要人工审批；满足前置条件且授权有效即可继续。

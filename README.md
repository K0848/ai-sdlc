# AI 产品研发工具包

**AI Product Development Toolkit** · 从产品判断到研发质量闭环，再到持续规划与交接恢复。

面向使用 AI 编程工具推进产品开发的产品经理与开发者，汇集产品指南、质量闭环 Skill 和文件规划 Skill。将需求评审、架构审查、实现反馈与测试验收组织成可复用工作流，以实际证据判断交付状态。

## 三个组成部分

| 组件 | 负责什么 | 入口 |
| --- | --- | --- |
| AI 产品指南 | 判断用户价值、能力边界、评测口径与产品取舍 | [产品指南](ai-guides/ai-pm-distillation.md) |
| AI 产品质量闭环 Skill | 组织需求、架构、测试准备和实现交付四个质量门 | [ai-product-quality-loop](skills/ai-product-quality-loop/SKILL.md) |
| 文件规划 Skill | 用持久化 Markdown 管理计划、当前状态、证据和交接恢复 | [planning-with-files-zh](skills/planning-with-files-zh/SKILL.md) |

仓库名称统一为 `ai-product-dev-toolkit`；两个 Skill 保留独立调用名，产品指南作为参考文档，不伪装成第三个 Skill。规划组件基于文件规划模式进行了中文化与本地规则适配；这里展示的是个人沉淀与组合，不宣称所有方法均为原创。

## 如何协同

产品指南用于澄清价值、能力、评测与决策边界。质量闭环按 Q1 需求评审 → Q2 架构评审 → Q3 测试与验证环境 → Q4 实现质量闭环推进。规划 Skill 保存当前进度和交接依据，帮助跨阶段、跨会话恢复。

一个质量门通过不代表后续阶段通过，也不等于用户价值已验证。契约变化时返回最早受影响阶段，复用仍有效的证据。

## 安装与调用

将仓库中的 `skills/` 和 `ai-guides/` 按相同层级部署到宿主配置根目录。以支持此目录布局的 Codex 环境为例：两个 Skill 分别位于配置根目录的 `skills/ai-product-quality-loop/` 和 `skills/planning-with-files-zh/`，产品指南位于 `ai-guides/ai-pm-distillation.md`。现有同名文件应先比较再合并，不直接覆盖个人规则。

其他 Agent 环境需要按其 Skill 加载机制安装，并保持产品指南的相对引用有效。具体调用语法以宿主为准，例如：

```text
使用 ai-product-quality-loop，基于本项目需求和当前产物判断应进入的质量门，
结合 planning-with-files-zh 维护项目计划与交接，推进实现和验证。
```

准备需求或 PRD、项目约束、代码库、验证环境以及可用的执行与审查能力。质量闭环要求显式调用；文件规划主要用于需要持续跟踪的产品工程项目，常规办公不会因工具步骤多而自动启用。

## 规划脚本与数据边界

规划 Skill 包含 Markdown 模板、PowerShell/Shell 初始化与完成检查脚本、Python 台账校验及会话恢复脚本。按所在平台选用对应脚本；Python 脚本需要可用的 Python 3，PowerShell/Shell 脚本需要相应解释器。

`session-catchup.py` 会读取本地 Codex 或 Claude 会话记录来辅助恢复，仅在允许访问这些记录的环境运行。仓库不包含个人会话日志、真实项目台账或凭据。`planning_hook.py` 是兼容历史配置的空操作占位，本包不要求安装 Hook。

## 运行条件与证据边界

这是指令、规范和辅助脚本的组合，不是独立运行的 Agent 引擎。工程/架构规范、执行工具、模型、权限和预算仍由宿主环境提供。产品指南提到的其他架构与 Agent 指南是扩展交接方向，本仓库未打包作者全部全局规则；涉及这些领域时应配置适用规则，缺失时明确说明。

当前发布仅核对文件、内部链接与脚本基础语法，不等于跨平台端到端使用验证。尚未附带可复现应用案例或效率对照数据，不宣称开发提速比例、通用成功率或生产可靠性保证。

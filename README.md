# AI 产品研发质量闭环 Skill

以需求、架构、测试与实现四个质量门，组织 AI 辅助开发与可验证交付。

面向使用 AI 编程工具推进产品开发的产品经理与开发者，将需求评审、架构设计、测试准备、实现反馈及交付验收组织为可复用工作流，并维护跨阶段的证据与恢复规则。

## 四个质量门

| 阶段 | 核心工作 | 通过意味着什么 |
| --- | --- | --- |
| Q1 需求评审 | 将需求转为可观察验收项，识别失败场景、边界与缺口 | 需求足够清楚，可以进入架构设计 |
| Q2 架构评审 | 明确模块、数据、状态、接口契约与恢复责任，按需验证技术可行性 | 方案可进入测试设计或限定范围的实现准备 |
| Q3 测试与验证环境评审 | 建立测试矩阵、实际运行入口、通过与停止条件 | 具备声明范围内的实现验证条件 |
| Q4 实现质量闭环 | 实现、验证、定位、修复、回归、独立审查及交付 | 声明范围有充分证据，阻塞关闭，未验证边界明确 |

一个质量门通过不代表后续阶段通过，也不等于用户价值已经验证。契约变化时返回最早受影响阶段，复用仍然有效的证据。

## 关键机制

- **证据关联**：完成结论关联验收项、当前产物版本、运行入口和验证证据，执行者自报完成不能关闭任务。
- **角色分工**：区分执行者、验证者与主记录者，独立审查使用新上下文与最小权威材料。
- **恢复与重试**：区分执行中、验证中、受阻与结果未知；外部副作用结果不明时先核对状态。
- **台账交接**：复用既有规划台账，通过稳定交接锚点恢复，不建立平行日志。
- **人机决策**：普通实现由执行者处理，目标、范围、成本、权限和重大风险变化交由用户确认。

## 使用与依赖

将本仓库目录作为 `ai-product-quality-loop` 放入所用 Agent 的 Skill 目录，保留文件相对结构。准备需求或 PRD、项目约束、代码库、验证环境以及可用的执行与审查能力，然后显式调用，例如：

```text
使用 ai-product-quality-loop，基于本项目需求和当前产物，
判断应进入的质量门，确认范围与验收条件，推进实现及验证。
```

具体安装位置与调用语法以所用 Agent 为准。本仓库保留作者当前 Skill 原文，以下本机配套规则未包含在仓库中，使用前需配置：

- **产品指南**：`SKILL.md` 和需求评审参考指向 Skill 目录之外的 `ai-guides/ai-pm-distillation.md`。这两处链接是宿主环境依赖，在 GitHub 仓库内无法打开；迁移时需提供自己的产品指南并调整对应引用。
- **规划 Skill**：使用 `planning-with-files-zh` 的台账约定，涉及 `.claude/` 下的计划、进度、发现、历史与决策文件。使用前需配置该 Skill 或适配已有台账规则。
- **工程与架构规则**：沿用宿主环境的适用指南、授权及工具能力，仓库未打包作者的全局配置。

缺少必要依赖或验证能力时，应明确缺口与受影响范围，不将未执行步骤标为通过。

## 证据边界

本仓库发布工作流指令和参考规范，未包含运行时强制执行引擎。实际效果依赖 Agent、项目工具、配套规则及真实验证。仓库尚未附带可复现应用案例或效率对照数据，不宣称开发提速比例、通用成功率或生产可靠性保证。
